🔄 Quick Recap: The 4 Levers of a Great Prompt

Before we build anything, let's refresh the rules. A great prompt has 4 parts:

🎭

Role

"You are a friendly shopping assistant for kids..."

📋

Context

"I'm building a kids' online store using Next.js..."

✅

Task

"Create a product card component that shows name, price, and image..."

📐

Format

"Use Material UI, keep code in one file, add comments explaining each part..."

The magic formula: Role + Context + Task + Format = AI actually understands what you want.

⚔️ Good vs. Bad: Prompt Battle!

Same goal. Very different results. Spot what's missing in the bad prompt — then see how the good one fixes it.

Example 1: Writing a story

❌ Bad Prompt
Write me a story.

Missing: Who is it for? What genre? How long? What should happen?

✅ Good Prompt
You are a children's author. Write a 3-paragraph adventure story for a 7th grader about a robot who discovers a hidden underwater city. End with a cliffhanger. Use short sentences.

Role Context Task Format

Example 2: Getting help with code

❌ Bad Prompt
Fix my code.

Missing: What code? What is it supposed to do? What's the error?

✅ Good Prompt
My shopping cart adds the same item twice when I click Add to Cart once. Find the bug and fix it. Explain what was wrong.

Context Task Format + specific problem

❌ Bad Prompt
Explain React.

Way too broad — could get a 5-word answer or a 50-page textbook.

✅ Good Prompt
You are a teacher. Explain what React components are to a 7th grader who knows what HTML is but has never coded before. Use a real-life analogy and keep it under 5 sentences.

Role Context Task Format

🧠 What Is Vibe Coding?

Vibe coding (coined by Andrej Karpathy, ex-Tesla AI director): You describe what you want to build in plain English. AI writes the code. You read, test, tweak, and iterate. You never need to memorize syntax.

What you DO need: Understanding of frontend/backend (Week 2) + great prompts (Weeks 4–5). That's it. That's your toolkit.

🔄 How Building with Claude Code Actually Works

Every screen we build will follow the same 4-step loop. You'll do it 5 times today.

1

💬 You describe

Type what you want in plain English into Claude Code. No code. No tech words you don't know. Just what the screen should look like and do.

2

🤖 Claude Code builds

It writes or edits the files, installs any packages it needs, and tells you what it did. You watch it happen — you don't type any code.

3

🌐 You look at your browser

Open localhost:3000 and refresh. Does it look right? Does it work? Click around and try it.

4

🔄 You describe what to change

"Make the buttons bigger." "The cart icon should be orange, not blue." "Add a star rating." Claude Code updates the files. Repeat.

🧠 Claude Code remembers. Everything you've said in the same session stays in its memory. You don't need to re-explain what you're building every time — just keep the conversation going.

🚨 One rule: After Claude Code makes a change, always check your browser before asking for the next change. If you skip testing, bugs pile up and get confusing.

🧰 Meet the 4 Tools Claude Code Will Use

In the next prompt you'll see 4 tech words. You won't type any of them. Just learn the names and what they do — so when Claude Code uses them, you know what's happening.

🍳

Next.js 14

The kitchen where modern web apps are cooked. It handles pages, clicking around, and everything "web-app-y" so you don't have to build that stuff yourself.

✏️

TypeScript

JavaScript with spell-check. It catches your typos and mistakes before your app breaks — like autocorrect, but for code.

🗺️

App Router

The map inside your app. It decides: "when someone visits /cart, show the cart page." You just name the pages — it figures out the rest.

🧱

Material UI v5

A box of ready-made Lego pieces from Google. Buttons, cards, menus, forms — already styled and ready to use. No designing from scratch.

🤖 The good news: Claude Code knows all four tools by name. You just say "use Next.js 14, TypeScript, App Router, and Material UI" and it handles every detail — installing, configuring, wiring them together.

🎯 Your job today: Don't memorize what these do under the hood. Just remember their names. When a friend asks "what did you build with?" you can answer — that's enough for a 7th grader's first web app.

🐛 When Things Break: Just Tell Claude Code

Things will break. That's normal. With Claude Code, debugging is just another conversation.

1

Describe what's wrong in plain English

"The cart number doesn't change when I click Add to Cart." "The checkout button doesn't do anything." "The product images are broken." — that's enough. No error messages needed.

2

Let Claude Code investigate

Claude Code reads your files itself. It finds the bug. It tells you what was wrong and fixes it. You don't need to paste code or errors.

3

Always ask "Why did this happen?"

Don't just accept the fix — ask Claude Code to explain the bug in simple language. That's how you actually learn.

4

Refresh your browser

Next.js reloads on its own when files change. Just go back to localhost:3000 and refresh (Cmd+R / Ctrl+R) to see the fix.

🦾 The Vibe Coder Mindset: "I don't memorize how to fix every bug. I describe what I see, and let my AI teammate handle the rest — then ask it to teach me what went wrong."
