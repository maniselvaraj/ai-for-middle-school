🔄 Quick Recap: The 4 Levers of a Great Prompt

Before we build anything, let's refresh the rules. A great prompt has 4 parts:

🎭

Role

"You are a friendly shopping assistant for kids..."

📋

Context

"I'm building a kids' online store using Next.js..."

✅

Task

"Create a product card component that shows name, price, and image..."

📐

Format

"Use Material UI, keep code in one file, add comments explaining each part..."

The magic formula: Role + Context + Task + Format = AI actually understands what you want.

🧠 Why System Prompts Are a Superpower

A system prompt is a set of invisible instructions you give the AI before the conversation starts. It shapes how the AI behaves for your entire session.

Without a system prompt:

You say Help me build a website.
AI replies Sure! What kind of website? Do you want HTML/CSS? React? Django? WordPress? I can... [3 paragraphs of generic questions]

With a system prompt:

System Prompt You are a coding assistant for 7th graders building a Next.js app. Always write clean code with comments. Use Material UI. Keep responses beginner-friendly.
Now you just say Help me build a website.

Think of the system prompt as hiring someone. The system prompt is the job description. Every response they give you follows those rules — no need to repeat yourself every time!

System Prompt We'll Use Today You are an expert Next.js developer helping 7th grade students build their first web app. Write all code using Next.js 14 (App Router), TypeScript, and Material UI v5. Keep folder structures clean, separate frontend and backend clearly, add helpful comments to every file, and explain what each piece of code does in simple language. Never use a database — store everything in memory arrays.

⚔️ Good vs. Bad: Prompt Battle!

Same goal. Very different results. Spot what's missing in the bad prompt — then see how the good one fixes it.

Example 1: Writing a story

❌ Bad Prompt
Write me a story.

Missing: Who is it for? What genre? How long? What should happen?

✅ Good Prompt
You are a children's author. Write a 3-paragraph adventure story for a 7th grader about a robot who discovers a hidden underwater city. End with a cliffhanger. Use short sentences.

Role Context Task Format

Example 2: Getting help with code

❌ Bad Prompt
Fix my code.

Missing: What code? What is it supposed to do? What's the error?

✅ Good Prompt
I'm building a Next.js shopping cart. My addToCart function adds the same item twice when clicked once. Here's the code: [paste code]. Fix the bug and explain why it was happening.

Context Task Format + specific error

❌ Bad Prompt
Explain React.

Way too broad — could get a 5-word answer or a 50-page textbook.

✅ Good Prompt
You are a teacher. Explain what React components are to a 7th grader who knows what HTML is but has never coded before. Use a real-life analogy and keep it under 5 sentences.

Role Context Task Format

🧠 What Is Vibe Coding?

Vibe coding (coined by Andrej Karpathy, ex-Tesla AI director): You describe what you want to build in plain English. AI writes the code. You read, test, tweak, and iterate. You never need to memorize syntax.

📋 What Is a Spec — and Why Write One First?

Before any professional software team writes a single line of code, they write a spec.

A spec (short for "specification") is a plain-English document that describes what an app does — who uses it, what screens it has, what you can do on each screen, and what it should NOT do.

❌

Without a spec

You start building, AI makes assumptions, features creep in, you lose track of what you wanted, and the app gets messy fast.

✅

With a spec

Every prompt references the spec. AI always knows what you're building. No confusion. Every piece fits together.

💡

Today's plan — in order

Step 1: Prompt AI to write our spec (plain English, no code)
Step 2: Read it together — does it describe what we want?
Step 3: Use the spec as context for every build prompt that follows

Real world connection: At companies like Apple, Google, and Meta — engineers, designers, and product managers all start with a spec document before any code is written. You're working like a real software team today.

Write a SPEC.md document for an app called "Amazon Jr." — a simple online store for kids. Write everything in plain English. No code. No technical jargon. Imagine you're explaining it to a 12-year-old.

The app must have exactly these 5 screens:
1. Homepage — a grid of 8 kid-friendly products (photo, name, price, "Add to Cart" button). Filter by category.
2. Product Detail Page — click a product to see a bigger photo, full description, star rating, and "Add to Cart" button.
3. Shopping Cart — shows everything added, quantities you can change, a remove button, and total price. Button to go to checkout.
4. Checkout Page — a simple form (first name, last name, email, address). No login, no password. Guest checkout only. Shows order summary.
5. Order Confirmation — big checkmark, order number, friendly message, button to go back to shopping.

Rules for this app:
- No login or accounts
- No database — cart and orders reset when browser closes
- 8 products with fun names, short descriptions, prices between $5–$60
- Colorful, kid-friendly design using Material UI
- Keep it simple — no wishlist, no reviews, no recommendations

Format the spec with these sections: App Name & Purpose, Who Uses It, The 5 Screens (one subsection each), What It Does NOT Do, Tech Stack.

After you get the spec: Read it out loud together. Ask: "Does this describe what we want to build?" If anything is wrong, fix the spec before writing any code.

💾 Important — Save it as a file! Copy the spec Claude gave you. In VS Code, create a new file in your project folder, name it SPEC.md, paste the spec in, and save. Every build prompt from here will reference this file by name.

📖 Read the Spec Together

Here's what a good spec looks like after AI generates it. Let's walk through each section.

SPEC.md — Amazon Jr.
## App Name & Purpose
Amazon Jr. is a simple online store where kids can browse fun products, add them to a cart, and place a pretend order — no account needed.

## Who Uses It
Kids aged 10–14 who want to practice online shopping on a safe, simple website.

## The 5 Screens
Homepage: Shows 8 products as cards in a 3-column grid. Each card has a photo, name, price, category tag, and "Add to Cart" button. Filter buttons at the top let you show only Toys, Books, Games, Art, or Sports.

Product Detail Page: When you click a product card, you see a full-page view with a larger photo, full description, star rating, stock count, and a big "Add to Cart" button. A "Back to Shop" link returns you to the homepage.

Shopping Cart: A list of everything in the cart. Each row shows photo, name, price, + / - quantity buttons, subtotal, and a remove button. A summary box shows subtotal, shipping (free over $35), and total. "Proceed to Checkout" button at the bottom.

Checkout Page: A simple form with 5 fields: First Name, Last Name, Email, Street Address, City & Zip. Order summary on the right. "Place Order" button submits.

Confirmation Page: Big green checkmark. "Order Placed!" heading. Your order number (like AJR-48291). "Your stuff is on the way! 📦" Shop More button.

## What It Does NOT Do
No user accounts, no payment processing, no real orders, no database, no product reviews, no search bar.

## Tech Stack
Next.js 14, TypeScript, Material UI v5, React Context for cart (in-memory only).

🐛 Debugging Is Part of the Vibe

Things will break. That's normal. That's how every developer works. Here's your debugging toolkit:

1

Read the Error Message First

Don't panic! Look for the red text in your Terminal window. It usually tells you exactly which file and which line number has the problem.

2

Paste It Into Claude — With the Spec

Copy the error text + the broken file. Also paste the spec so Claude understands what you're building. Say: "Here's my spec, here's the error, here's the file — fix it and explain what went wrong."

3

Ask "Why Did This Happen?"

Don't just copy the fix — ask Claude to explain the bug in plain English. You'll never forget it.

4

Save → Terminal → Refresh

After pasting fixed code into VS Code: save the file (Ctrl+S / Cmd+S), check the Terminal (Next.js auto-reloads), then refresh your browser.

🦾 The Vibe Coder Mindset: "I don't need to memorize how to fix every bug. I need to know how to describe it clearly to AI — and how to understand the answer." That's the real skill.
